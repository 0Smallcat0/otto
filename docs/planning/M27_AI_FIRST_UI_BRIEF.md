## 0. 為什麼大改

Owner 2026-07-07 拍板「對話即介面、AI 全權操作」後指出:*「都交由 AI 操控了,需要展示出來的東西也要改變。」*
舊 UI 是給「動手操作的人」的駕駛艙(15 工作區、大量按鈕表單)。操作者變成 AI 之後,人剩下的工作只有四件,全部是「看」:

1. **看 AI 在幹嘛**(activity feed;資料層 `agent_activity_event` 已存在)
2. **讀 AI 的產出**(回測報告/研究簡報/portfolio 分析——攤開的答案,不是原始面板)
3. **檢查信任**(資料鮮度、安全閘門、備份、key 狀態——M26 全部有 API)
4. **瞄一眼行情**(電視牆式 glance)

→ 設計綱領:**從駕駛艙到任務牆**。按鈕退場,顯示升級。

## 1. Owner 三個定向決策(2026-07-07,AskUserQuestion 原文)

| 問題 | 決定 | 含義 |
|---|---|---|
| 使用型態 | **兩種都要** | 首頁=一眼看懂的任務牆;點進去=細讀模式(報告/簡報全文) |
| 舊 15 工作區 | **大刀砍掉重練** | 前端全面重建,不保留舊面板;e2e 測試整套隨新 UI 重寫 |
| 網頁對話口 | **不用** | 網頁純展示;指令永遠走 Claude Code 對話。UI 上零輸入表單 |

## 2. 新資訊架構(mockup 據此製作)

- **頂部信任條**:系統狀態、LIVE TRADING 鎖、備份狀態、key 數、時鐘
- **行情帶**:大字報價 + 迷你走勢(crypto/美股/FX/總經利率——資料全部已有)
- **主欄:AI 活動流**:每列=時間+動詞+對象+結果 chip+「查看產出→」;進行中項目呼吸燈
- **側欄:最新產出卡**(點開進細讀模式)+ **信任面板**(鮮度/閘門/備份/keys)
- **細讀模式**:報告當文件排版(指標格、曲線、交易表、artifact 路徑腳註),有「回任務牆」
- 全站無輸入框、無操作按鈕(唯一例外:主題切換等純顯示偏好)

## 3. 邊界與風險

- **後端零改動**:M26 的 contract/備份/測試全部沿用;新前端只是換一雙眼睛
- **e2e 整套重寫**(舊 e2e 文案耦合,砍面板必死)——列入施工計畫首批 slice
- 舊 `styles.css` 亮色主題/theme 系統:重建時保留「有亮暗兩主題」的能力,實作可換
- M25 剩餘美化**就此中止**(避免對將拆的 UI 白工);M25 里程碑收束併入 M27
- M26 Phase 2 候選(activity feed、custom watchlist、undo)**併入 M27** 依新典範實作
